How letters become 16-bit words

A computer stores every letter as a number. The checksum needs 16-bit words, so letters are turned into bits first.

  1. Find the character code. Every character has a number in the ASCII table. For example H is 72 and i is 105.
  2. Write the code in binary using 8 bits. 72 becomes 01001000 and 105 becomes 01101001. Add zeros on the left until there are 8 bits.
  3. Join two characters to make one 16-bit word. The first character goes on the left, the second on the right: 01001000 01101001.
  4. If one character is left over, add 00000000 after it so it still makes 16 bits. RFC 1071 pads with zeros in the same way.

The ideas behind it

Short answers, written for a first-year student.

What is an Internet Checksum?

A small 16-bit number worked out from the data. The sender attaches it, and the receiver repeats the sum. If the data changed on the way, the numbers will not match and the error is noticed.

What is one's complement addition?

Normal binary addition on 16-bit numbers with one extra rule: if the answer needs a 17th bit, that extra bit is added back into the answer.

What is end-around carry?

The carry that falls off the left end is brought around to the right end and added to the lowest bit. In the working panel it shows up in pink.

What is one's complement?

Flip every bit: 0 becomes 1 and 1 becomes 0. For example 1010 becomes 0101. It is what the bits do in the strip at the top of the page.

Why is a checksum used?

Noise can corrupt data while it travels. A checksum is a cheap, quick way to notice that something went wrong.

Where is it used?

In the headers of IPv4, TCP and UDP. RFC 1071 explains how it is computed.

Error detection or error correction?

Error detection only tells you that an error happened (checksum, parity, CRC). Error correction also finds and repairs the wrong bits (for example Hamming code). The Internet Checksum only detects. When it finds an error, the packet is dropped or sent again.
